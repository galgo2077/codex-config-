# Git rules

Use Git to preserve meaningful progress without routine overhead. Read relevant status or diff before modification only when useful.

Do not repeatedly run status diff or log after tiny operations. Inspect the relevant diff once before completion.

Commit only a verified logical change checkpoint before risky work or when explicitly requested. Do not commit broken intermediate work generated noise secrets or temporary debugging files. Do not push without explicit authorization or an established requested workflow.

Keep branch and commit names short and precise. Preserve user changes. Do not rewrite shared history or use destructive reset or checkout without explicit need.

Test affected behavior before merge. Do not merge known failures.
