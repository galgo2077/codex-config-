# Targeted security rules

Load this module for authentication authorization secrets credentials cookies sessions permissions user-controlled input SQL filesystem paths shell execution network exposure CORS XSS cryptography financial execution or destructive operations.

Do not run a generic security audit for unrelated internal code configuration or documentation.

Protect secrets from source logs output command history tests vault notes and Git. Use least privilege safe parsers validation at trust boundaries and low-impact checks on user-owned or authorized targets only.

Confirm findings before changing code. Fix the root cause. Use only the security tool needed for the identified surface. Avoid destructive testing denial of service brute force unrelated data extraction and security theater.

Before publishing or pushing security-sensitive changes inspect the relevant diff and staged content for secrets and unsafe configuration.
