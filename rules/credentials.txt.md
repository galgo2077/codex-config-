CREDENTIAL RULES

USE FREEDESKTOP SECRET SERVICE AS THE PRIMARY AND ONLY CREDENTIAL STORE.
CODEX MAY LIST SEARCH GET CREATE UPDATE USE AND TEST SAVED CREDENTIALS.
DELETE A CREDENTIAL ONLY WHEN THE USER EXPLICITLY REQUESTS DELETION.
IF SECRET SERVICE FAILS STOP THE AUTHENTICATED TASK AND NEVER USE A PLAINTEXT FALLBACK.

STORE METADATA: STORE NAME SERVICE WEBSITE DOMAIN USERNAME TYPE PROJECT HOST NOTES.
STORE THE SECRET VALUE ONLY INSIDE SECRET SERVICE.
NEVER STORE RAW SECRETS IN CODEX CONFIG AGENTS FILES PROJECT FILES GIT OBSIDIAN NOTES LOGS OR BACKUPS.
OBSIDIAN MAY STORE ONLY SECRET ID SERVICE WEBSITE USERNAME PURPOSE PROJECT AND MACHINE REFERENCES.

GLOBAL HELPER: `/home/galgo/.codex/bin/codex-secret` OR `$CODEX_CREDENTIAL_HELPER`.
USE `list`, `search`, OR `lookup` FOR METADATA; THESE OPERATIONS MUST NOT LOAD OR PRINT SECRETS.
USE `create` AND `update --secret-stdin` WITH THE SECRET ON STDIN.
USE `get --fd 3` ONLY WITH A PRIVATE FILE DESCRIPTOR; NEVER DIRECT IT TO MODEL OUTPUT.
PREFER `exec` TO INJECT THE SECRET INTO ONE PROCESS THROUGH STDIN; USE `exec --env NAME` ONLY WHEN THE TARGET REQUIRES AN ENVIRONMENT VARIABLE.
NEVER PUT A SECRET IN COMMAND ARGUMENTS OR SHELL HISTORY.

WHEN AUTHENTICATION IS NEEDED SEARCH SECRET SERVICE FIRST BY SERVICE WEBSITE DOMAIN HOST PROJECT AND USERNAME.
SELECT THE BEST VALID MATCH. DO NOT ASK THE USER WHEN A VALID MATCH EXISTS.
DO NOT GUESS WHEN MULTIPLE CREDENTIALS TIE.
LOAD THE SECRET ONLY AT EXECUTION TIME AND KEEP ITS LIFETIME SHORT.

FOR WEB AUTHENTICATION REQUIRE A MATCHING SAVED WEBSITE OR DOMAIN, VERIFY DOMAIN BOUNDARIES, AND REQUIRE HTTPS EXCEPT LOCALHOST.
USE A CREDENTIAL ONLY FOR ITS MATCHING SERVICE.
DO NOT DISABLE TLS VALIDATION.

WHEN THE USER PROVIDES OR CODEX GENERATES A NEW PASSWORD TOKEN API KEY LOGIN OR OTHER SECRET, SAVE IT AUTOMATICALLY WITH CORRECT METADATA AND VERIFY STORAGE.
WHEN A CREDENTIAL CHANGES UPDATE SECRET SERVICE AND REMOVE THE STALE VALUE.

PREFER SSH KEYS AND SSH AGENT. STORE SSH PASSWORDS OR RELATED AUTH DATA IN SECRET SERVICE ONLY.
SSH CONFIG AND `/ssh session` MAY CONTAIN A CREDENTIAL ID OR KEY PATH, NEVER A PASSWORD OR PRIVATE KEY CONTENT.

GIVE AUTHENTICATION ONLY TO THE TOOL OR PROCESS THAT REQUIRES IT.
NEVER SEND RAW SECRETS TO SUBAGENTS, OBSIDIAN, PONYTAIL, ROUNDTABLE, CONTEXT7, SEARXNG, OR AN UNRELATED MCP.
